# ssh-gateway

Единственный путь агентов Fugu Deck к серверам пользователей (`docs/ARCHITECTURE-v2.md`, раздел 7). В пространстве агента
нет ни ключей, ни сертификатов: команду он может только попросить выполнить.

| Кто | Запрос | Что |
|---|---|---|
| control-plane | `POST /v1/servers {"jws"}` | подписанное владельцем `server_add`: адрес, пользователь, отпечаток ключа хоста |
| control-plane | `POST /v1/rights {"jws"}` | подписанное `agent_rights`: к каким серверам допущен агент, можно ли читать без подтверждения |
| control-plane | `POST /v1/servers/remove`, `POST /v1/state` | убрать сервер (уменьшение прав, без подписи); серверы, права, ключ CA — для экрана приложения |
| агент пространства | `POST /v1/agent/servers`, `/v1/agent/check` | свои серверы; уровень команды и какая подпись понадобится |
| агент пространства | `POST /v1/agent/exec {"agent","server","command","jws"}` | выполнить команду |

Вызывающих шлюз опознаёт по проецируемому токену ServiceAccount с audience `ssh-gateway` (TokenReview).

## Что проверяется перед командой

1. Агент этого пространства допущен к серверу подписанным `agent_rights`.
2. Уровень команды (`classify.go`): **чтение** — короткий список команд без каких-либо средств оболочки; **опасное** —
   разрушительные команды и пути; всё остальное — **запись**.
3. Чтение идёт без подтверждения, только если владелец разрешил это подписью. Запись требует действия `ssh_write`,
   опасное — `ssh_danger` (с введённым именем сервера), подписанного владельцем **на эту самую команду**. Подпись проверяет
   keyguard; каждая годится один раз.
4. Адрес сервера публичный (не кластер, не частная сеть, не метаданные облака), ключ хоста совпадает с подписанным.

Затем шлюз создаёт ключ на одну команду, получает в OpenBao (`ssh-client-signer/sign/agent`) сертификат на 10 минут с
principal `deck-<пространство>-<агент>` и выполняет команду без терминала, с таймаутом и ограничением вывода. На сервере —
одна команда за раз; у агента — лимит команд в час.

Разбор команд — удобство для человека, а не граница безопасности. Граница — права пользователя на сервере.

## Настройка сервера пользователя

```
useradd -m deck-agent                                  # не root; sudo — только на нужные команды
echo '<ключ CA из приложения>' > /etc/ssh/deck_ca.pub
cat >> /etc/ssh/sshd_config <<CFG
TrustedUserCAKeys /etc/ssh/deck_ca.pub
AuthorizedPrincipalsFile /etc/ssh/principals/%u
CFG
mkdir -p /etc/ssh/principals && echo 'deck-u-<ник>-fugu' > /etc/ssh/principals/deck-agent
systemctl reload ssh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub       # отпечаток SHA256:… — его вводят в приложении
```

## Состояние

Проверенные привязки (серверы и права) лежат в одном файле JSON на томе шлюза (`DECK_STATE_FILE`): подпись нельзя
проверить второй раз, поэтому результат проверки хранит сам шлюз. Потерян том — владельцы добавляют серверы заново.

## Что есть сверх этого (D55, D56)

- **Пробный прогон** (`preview`): до подтверждения шлюз выполняет безопасную проверку (`terraform plan`, `kubectl diff`,
  `--dry-run`, `apt-get -s`, `rsync -n` …), и человек видит настоящий вывод.
- **Журнал команд** (`journal.jsonl` на томе, 30 дней, до 500 записей на пространство, первые 4 КБ вывода) —
  `GET /v1/journal`, экран серверов.
- **Остановка агента на серверах** (`/v1/pause`): идущие команды обрываются, новые — 423 до возобновления.
- **Общие пространства**: команды подписывает владелец общего пространства — шлюз узнаёт его сам из объекта Space.
- **Несколько агентов**: права у каждого свои, principal — `deck-<пространство>-<агент>`.
- Независимая проверка команды отдельной моделью — в агенте пространства (подсказка человеку перед подписью).

## Чего нет

Постоянного ключа вместо CA («способ 2»); правила двух людей (кто второй подписывающий — не решено); сетевой политики
на каждый сервер (исходящий доступ шлюза — весь интернет, проверка адреса — в коде: шлюзу пришлось бы менять
чувствительный namespace мимо git); копии состояния шлюза (серверы и права — файл на томе; потерян том — серверы
добавляют заново; копия в Postgres требует секрета в OpenBao, а он записывается кворумом); снимка диска перед
изменением (нужен API провайдера сервера).

## Проверка

- `go test ./...` — классификатор, подписи, лимиты и выполнение по настоящему SSH: в тесте поднимается SSH-сервер,
  доверяющий своему CA и пускающий только названный principal.
- `scripts/sshd_test.sh` — настоящий OpenBao (SSH CA с ролью `agent`, как в `terraform/openbao/main.tf`) и настоящий
  sshd в контейнере, настроенный командами из приложения: сертификат принимается; чужой principal, чужой исходящий
  адрес и чужой ключ хоста — нет; терминала нет; зависшая команда обрывается.
